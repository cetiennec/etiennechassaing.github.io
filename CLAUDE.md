# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

Personal academic CV website (etiennechassaing.com) built with Hugo and the Hugo Blox Builder "Academic CV" theme. Deployed to GitHub Pages via `.github/workflows/publish.yaml` on every push to `main` (a `netlify.toml` also exists but GitHub Pages is the active deployment, per `CNAME`).

## Commands

Requires Hugo **extended** v0.126.3 (the version pinned in the workflow and netlify.toml) and Go (theme is pulled in as Hugo modules via `go.mod`).

```bash
hugo server            # local dev server with live reload
hugo --minify          # production build into public/
```

There are no tests or linters. `public/` and `resources/` are gitignored build output — never edit them.

## Architecture

- **Theme via Hugo modules** (`config/_default/module.yaml` / `go.mod`): `blox-tailwind`, `blox-plugin-netlify`, and a personal fork `github.com/cetiennec/hugo-blox-language_block` (custom language block). No vendored theme code; run `hugo mod` commands to update.
- **Bilingual site** (`config/_default/languages.yaml`): English content in `content/en/`, French in `content/fr/`. The two trees are not mirrors — French has extra sections (`formations/`, `enseignements/`, `projets/`, `projets-recherche/`) with their own names. Menus are per-language: `menus.yaml` (en) and `menus.fr.yaml`. `content/mock_posts/` sits outside both content dirs and is not published.
- **Homepage** (`content/{en,fr}/_index.md`): a `type: landing` page composed of Hugo Blox `sections:` blocks (resume-biography-3, markdown, collections, etc.). Most site-wide settings live in `config/_default/params.yaml`.
- **Publications pipeline**: `.github/workflows/import-publications.yml` runs when `publications.bib` changes; it converts BibTeX to Markdown with the `academic` CLI and opens a PR. Note it imports into `content/publication/` (repo root), while the live pages are under `content/en/publication/` and `content/fr/publication/` — imported entries need to be moved/translated into the language dirs.
- **`/book/` area** is now just the Jupyter Book of case studies (teaching material used to live under `/book/classes/` too, but that made no sense once "Classes" became its own menu entry — it's now at `/teaching/`, outside `/book/` entirely; see below).
  - `/book/` itself is a Hugo hub page (`content/{en,fr}/book/_index.md`). It is no longer in the menus — "Case Studies"/"Études de cas" and "Teaching"/"Enseignement" are separate entries — but it is kept so old `/book/` links still land somewhere.
  - **Menu URLs are language-prefixed**: the theme pipes every menu `url` through `relLangURL` (see `partials/components/headers/navbar.html`), so a `menus.fr.yaml` entry *always* resolves under `/fr/`, even if you write an absolute `https://…` URL — and it's idempotent, so an entry already written as `/fr/...` (like Enseignement) isn't double-prefixed. The Jupyter Book is language-agnostic, so `static/fr/book/case-studies/index.html` is a redirect stub sending `/fr/book/case-studies/` → `/book/case-studies/`.
  - **Jupyter Book at `/book/case-studies/`**: `static/book/case-studies/` is a committed, prebuilt Jupyter Book (Sphinx HTML) of control-engineering case studies (drone_delayed_control, fishing_boat, heat_pipe_control). Its source is **not in this repo** — to update it, rebuild the book elsewhere and copy the HTML output into `static/book/case-studies/` (see "Update Jupyter Book build" commits). Don't hand-edit these files. It used to live at `static/book/`; the loose `.html` files still sitting directly in `static/book/` are meta-refresh redirect stubs kept so old links (`/book/heat_pipe_control/system_tutorial.html`, …) keep working — regenerate them if the book gains pages. Note `disableAliases: true` in `hugo.yaml`, so Hugo `aliases:` front matter produces no redirects; static stubs are the mechanism.
- **Teaching material at `/teaching/`** (`content/{en,fr}/teaching/`). It moved `/book/classes/` → `/classes/` (Sept 2026) → `/teaching/` (Oct 2026); `static/{,fr/}book/classes/` and `static/{,fr/}classes/` hold meta-refresh stubs for every old page so those URLs still work — add one if a course page is added. PDFs are **not** committed here — they are served from the public repo `cetiennec/cours-pdf` via jsDelivr (`https://cdn.jsdelivr.net/gh/cetiennec/cours-pdf@main/<path>`), which unlike `raw.githubusercontent.com` returns `Content-Type: application/pdf` so PDFs can be embedded in an `<iframe>`. That repo is a mirror generated by `publier.sh` in the private `LatexClasses` repo: a PDF is public **iff** it sits in a `diffusion/` folder there. Corrections outside `diffusion/` (e.g. `examen_final_correction.pdf`) are deliberately private — don't transcribe or link them.
  - **One Teaching page, organised by school** (Oct 2026): `/teaching/` ("Teaching"/"Enseignement") is the only teaching menu entry. Each school is a sub-section with `weight` 1-5: `centralesupelec/`, `ece/`, `albertschool/`, `companies/` (title "Companies"/"Entreprises"), `epfl/`. A school's `_index.md` is a short overview; each class is a child page (`centralesupelec/reinforcement-learning/`, `robotics-elective/`, `robotics-project/`; `ece/control-systems/`, `autonomous-car-slam/`; `albertschool/mathematics-foundations/`; `companies/…`; `epfl/…`), ordered by `weight` and listed as cards by the `teaching-list` shortcode (pages and sub-sections; no param = the current section; `teaching_list: false` leaves a page out). The desktop docs sidebar is the `teaching` section tree, so it reads school → class with no custom layout; titles under a school don't repeat the school name. The ECE final exam has no page of its own: it is the last section of the course page (`ece/control-systems/index.md`, after the midterm quiz), with the exam PDF embedded and links to the answer sheet; every older exam URL is a redirect stub to that section's anchor (`#final-exam` / `#examen-final`). The Teaching page groups schools into "Courses I created" (CentraleSupélec, ECE, AlbertSchool), "Corporate training" (Companies), then "Other teaching" (EPFL, TA only). Same slugs in both languages. The old experience sections (`/teaching/<slug>/`, `/fr/enseignements/…`, `/fr/formations/…`) are gone; `static/teaching/`, `static/fr/enseignements/` and `static/fr/formations/` hold redirect stubs to the new paths. Copy style: no em dashes on the site (titles use a colon, " : " in French).
  - The Teaching page (`content/{en,fr}/teaching/_index.md`) opens with a `sorting-arm` shortcode: a small flat 2-DOF industrial-arm animation (closed-form IK + PD control, no dependency) that sorts the school logos into bins. Its code is `layouts/partials/sorting-arm-banner.html` (the drawing/physics), wrapped by `layouts/shortcodes/sorting-arm.html` (markdown pages) and `layouts/partials/blox/sorting-arm.html` (a Hugo Blox block, for `type: landing` pages).
  - Course pages embed PDFs from jsDelivr (the `pdf` shortcode, or a plain `<iframe>` for the ECE final exam). Math is per-page (`math: true`); the theme's KaTeX auto-render accepts both `$…$` and `$$…$$`.
- **Custom layout overrides**: `layouts/partials/components/sidebar.html` is a copy of the theme's docs sidebar with one addition: a page with `sidebar: { sections: true }` gets anchor shortcuts to its `###` sections under it (helper: `partials/functions/section-headings.html`); a section titled like one of the page's child pages is skipped. Re-copy it from the theme if the theme is updated. Other overrides: the CV page (`content/{en,fr}/experience.md`) uses a custom `cv-header` block plus local overrides of `partials/blox/resume-{experience,awards,skills,languages}.html` (shared item partial `partials/cv/item.html`, styles under the "CV page" section of `assets/css/custom.css`, strings `cv_*` in `i18n/`); education entries can list `courses:` (rendered as chips). Also `partials/blox/resume-biography-3.html`, `partials/hooks/head-end/github-button.html`, and the shortcodes `teaching-list` (SVG `featured` images are used as is, since Hugo can't resize them), `pdf` and `sorting-arm`.
