# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

Personal academic CV website (etiennechassaing.com) built with Hugo and the Hugo Blox Builder "Academic CV" theme. Deployed to GitHub Pages via `.github/workflows/publish.yaml` on every push to `main` (a `netlify.toml` also exists but GitHub Pages is the active deployment, per `CNAME`).

## Commands

Requires Hugo **extended** v0.126.3 (the version pinned in the workflow and netlify.toml) and Go (theme is pulled in as Hugo modules via `go.mod`).

```bash
hugo server            # local dev server with live reload
hugo --minify          # production build into public/
```

There are no tests or linters. `public/` and `resources/` are gitignored build output — never edit them.

## Architecture

- **Theme via Hugo modules** (`config/_default/module.yaml` / `go.mod`): `blox-tailwind`, `blox-plugin-netlify`, and a personal fork `github.com/cetiennec/hugo-blox-language_block` (custom language block). No vendored theme code; run `hugo mod` commands to update.
- **Bilingual site** (`config/_default/languages.yaml`): English content in `content/en/`, French in `content/fr/`. The two trees are not mirrors — French has extra sections (`formations/`, `enseignements/`, `projets/`, `projets-recherche/`) with their own names. Menus are per-language: `menus.yaml` (en) and `menus.fr.yaml`. `content/mock_posts/` sits outside both content dirs and is not published.
- **Homepage** (`content/{en,fr}/_index.md`): a `type: landing` page composed of Hugo Blox `sections:` blocks (resume-biography-3, markdown, collections, etc.). Most site-wide settings live in `config/_default/params.yaml`.
- **Publications pipeline**: `.github/workflows/import-publications.yml` runs when `publications.bib` changes; it converts BibTeX to Markdown with the `academic` CLI and opens a PR. Note it imports into `content/publication/` (repo root), while the live pages are under `content/en/publication/` and `content/fr/publication/` — imported entries need to be moved/translated into the language dirs.
- **`/book/` area** has three layers:
  - `/book/` itself is a Hugo hub page (`content/{en,fr}/book/_index.md`). It is no longer in the menus — "Case Studies"/"Études de cas" and "Classes"/"Cours" are separate entries — but it is kept so old `/book/` links still land somewhere.
  - **Menu URLs are language-prefixed**: the theme pipes every menu `url` through `relLangURL` (see `partials/components/headers/navbar.html`), so a `menus.fr.yaml` entry *always* resolves under `/fr/`, even if you write an absolute `https://…` URL. The Jupyter Book is language-agnostic, so `static/fr/book/case-studies/index.html` is a redirect stub sending `/fr/book/case-studies/` → `/book/case-studies/`.
  - **Jupyter Book at `/book/case-studies/`**: `static/book/case-studies/` is a committed, prebuilt Jupyter Book (Sphinx HTML) of control-engineering case studies (drone_delayed_control, fishing_boat, heat_pipe_control). Its source is **not in this repo** — to update it, rebuild the book elsewhere and copy the HTML output into `static/book/case-studies/` (see "Update Jupyter Book build" commits). Don't hand-edit these files. It used to live at `static/book/`; the loose `.html` files still sitting directly in `static/book/` are meta-refresh redirect stubs kept so old links (`/book/heat_pipe_control/system_tutorial.html`, …) keep working — regenerate them if the book gains pages. Note `disableAliases: true` in `hugo.yaml`, so Hugo `aliases:` front matter produces no redirects; static stubs are the mechanism.
  - **Teaching material at `/book/classes/`** (`content/{en,fr}/book/classes/`): PDFs are **not** committed here — they are served from the public repo `cetiennec/cours-pdf` via jsDelivr (`https://cdn.jsdelivr.net/gh/cetiennec/cours-pdf@main/<path>`), which unlike `raw.githubusercontent.com` returns `Content-Type: application/pdf` so PDFs can be embedded in an `<iframe>`. That repo is a mirror generated by `publier.sh` in the private `LatexClasses` repo: a PDF is public **iff** it sits in a `diffusion/` folder there. Corrections outside `diffusion/` (e.g. `examen_final_correction.pdf`) are deliberately private — don't transcribe or link them.
  - The ECE final exam is transcribed in full (questions only, no solutions) in `content/fr/book/classes/examen-final-ece/`, with TikZ/pgfplots figures rendered to SVG (`pdflatex` → `pdftocairo -svg`, white `<rect>` inserted so they stay legible in dark mode). The English page is a summary plus the embedded PDF, linking to the French transcription. Math is per-page (`math: true`); the theme's KaTeX auto-render accepts both `$…$` and `$$…$$`.
- **Custom layout overrides** are minimal: only `layouts/partials/hooks/head-end/github-button.html`.
